# 点签GEO领导交付说明

## 一句话介绍

点签GEO是基于企业知识库的 GEO 内容生产、审核和多平台分发系统，用于把可信业务资料持续转化为可管理、可发布、可追踪的内容资产。

## 演示目标

领导演示应重点回答三个问题：

1. 企业已有资料如何进入知识库并被 AI 使用。
2. AI 生成内容如何经过风险控制和人工审核。
3. 一篇内容如何发布到本站并扩展到其他平台。

## 推荐演示顺序

1. 打开知识库，展示业务资料和知识切片。
2. 打开 AI 配置器，说明 Chat 与 Embedding 模型分工。
3. 展示标题、作者、图片和提示词等内容资产。
4. 创建一个文章上限为 1 的测试任务。
5. 启动任务并查看队列执行状态。
6. 在内容管理中查看草稿、风险扫描和审核状态。
7. 审核并发布文章，在前台查看最终页面。
8. 展示数据分析和今日头条、WordPress、通用 API 等分发能力。

## 演示口径

建议使用以下表述：

> 点签GEO基于成熟的 Apache-2.0 开源底座进行二次开发，完成了品牌重构、本地化部署、国产模型接入、内容生产流程和业务交付适配。

不要表述为完全从零自研，也不要把模型生成结果描述为无需审核即可直接发布。

## 当前本地地址

- 前台：`http://localhost:18080/`
- 后台：`http://localhost:18080/geo_admin/`

地址仅用于本机演示。部署到服务器时应配置正式域名、HTTPS、可信代理和生产环境变量。

## 已知边界

- 微信公众号当前支持复制微信富文本，自动发布需要官方接口适配。
- 今日头条已提供内置渠道、队列重试和远端结果回写；正式自动发布仍需企业头条号获批的官方接口或合规接入服务。
- 百家号、知乎和小红书尚无内置发布器。
- 通用 HTTP API 适用于自建 CMS、内部系统或平台接入网关。
- 外部平台发布能力取决于企业账号权限和平台开放接口。
- 当前本机 Docker Desktop 会把 DashScope 解析到保留地址代理，因此本机 `.env` 配置了精确的 `dashscope.aliyuncs.com:443` 出站例外；环境变量样例保持为空，服务器部署时必须根据实际 DNS 结果重新审查，不应直接复制本机例外。

## 技术交接入口

- Web、API 与调度入口：`routes/`
- 内容生产编排：`app/Services/GeoFlow/WorkerExecutionService.php`
- 知识检索：`app/Services/GeoFlow/KnowledgeRetrievalService.php`
- 风险门禁：`app/Services/GeoFlow/ArticleRiskGate.php`
- 多渠道分发：`app/Services/GeoFlow/DistributionOrchestrator.php`
- 容器编排：`docker-compose.yml`
